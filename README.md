# Cookie Cloud

**Automatic, self-hosted cloud save synchronization for Cookie Clicker.**

Cookie Cloud is a Cookie Clicker mod by [KingNullboy](https://github.com/KingNullboy) that automatically synchronizes your game saves with a Cookie Cloud server of your choice.

Cookie Cloud is not tied to NullWeb. Anyone can host their own server and use it to back up and synchronize their Cookie Clicker progress.

## Features

- **Automatic synchronization** — Automatically uploads your game save when Cookie Clicker saves.
- **Cloud save loading** — Loads your existing cloud save when the game starts.
- **Automatic initial setup** — Creates a cloud save from your local game if one doesn't exist.
- **Debounced uploads** — Waits two seconds after a save before uploading, reducing unnecessary requests.
- **Revision tracking** — Tracks cloud save revisions to detect conflicting changes.
- **Conflict resolution** — Lets you choose whether to overwrite a newer cloud save or load it.
- **Self-hosted servers** — Connect to any compatible Cookie Cloud server.
- **Configurable API endpoint** — Choose which server stores your cloud saves.
- **Steam achievements** — Compatible with Steam achievements.

## Requirements

- Cookie Clicker version 2.052 or compatible.
- A Cookie Cloud server.
- An API token generated by your chosen server.

You do not need a NullWeb account to use Cookie Cloud.

## Installation

1. Install Cookie Cloud through Cookie Clicker's mod manager, or load the mod using your preferred mod installation method.
2. Start Cookie Clicker.
3. When prompted, enter your Cookie Cloud server URL.
4. Enter an API token generated by that server.
5. Cookie Cloud will connect and begin synchronizing your saves.

Enter the server's base URL, not its API endpoint.

For example:

```text
https://nullweb.org
```

Cookie Cloud automatically appends `/api/cookie`.

Your server URL and API token are stored locally in your browser's `localStorage`:

- `CookieCloudServer`
- `CookieCloudToken`

## Self-Hosting

Cookie Cloud supports independently hosted servers.

Server administrators can deploy their own compatible Cookie Cloud API and manage API tokens for their users.

Each server maintains its own database, meaning saves stored on one server are completely separate from saves stored on another.

See the server's documentation for installation, configuration, database setup, and token management.

### Server Compatibility

Cookie Cloud clients communicate using the same API protocol regardless of which server they connect to.

A compatible server must implement:

- `GET /api/cookie/status`
- `GET /api/cookie/save`
- `PUT /api/cookie/save`
- `DELETE /api/cookie/save`

The API must support Bearer token authentication using `nwc_`-prefixed tokens and revision-based save conflict detection.

## How It Works

Cookie Cloud hooks into Cookie Clicker's save and load functions.

When the game saves, Cookie Cloud captures the current save data and schedules an upload. Uploads are delayed by two seconds to avoid sending unnecessary requests during frequent saves.

When Cookie Clicker starts, Cookie Cloud checks the configured server for an existing cloud save:

- If a cloud save exists, it downloads and loads it.
- If no cloud save exists, it uploads the current local save.

Cloud saves use revision tracking to prevent accidental overwrites when multiple game instances have different versions of the save.

### Conflict Resolution

If a save upload encounters a revision conflict, Cookie Cloud retrieves the latest cloud save and asks how to proceed.

- **OK:** Overwrite the cloud save with the local save.
- **Cancel:** Discard pending local snapshots and load the cloud save.

## API

Cookie Cloud communicates with the configured server using the Cookie Cloud API.

| Endpoint | Method | Purpose |
|---|---|---|
| `/api/cookie/status` | GET | Check whether a cloud save exists and retrieve its revision. |
| `/api/cookie/save` | GET | Download the current cloud save. |
| `/api/cookie/save` | PUT | Upload a save with revision checking. |
| `/api/cookie/save` | DELETE | Delete the current cloud save. |

Requests use Bearer token authentication.

Save uploads include:

- `saveData` — The Cookie Clicker save string.
- `expectedRevision` — The revision the client expects to overwrite.

The API uses revision tracking and SHA-256 integrity checks. Servers may compress saves internally using Zstandard.

## Configuration

The server URL is saved locally and can be configured when connecting:

```js
localStorage.getItem('CookieCloudServer')
```

The API token is stored locally:

```js
localStorage.getItem('CookieCloudToken')
```

The configured server URL is a base URL. The client automatically appends `/api/cookie`.

To use a different server, disconnect and reconnect using its URL and a valid API token.

## Troubleshooting

**Cookie Cloud cannot connect**

- Verify that your server URL is correct.
- Verify that your API token is valid and has the required permissions.
- Check your internet connection.
- Ensure your server is running and accessible.
- Open the browser developer console and look for `[Cookie Cloud]` messages.

**Startup synchronization failed**

- Check the console for the underlying API error.
- Verify that the server's Cookie Cloud API is available.
- Check that your token has the `save:read` permission.

**Upload failed**

- Check your connection and API token.
- Verify that your token has the `save:write` permission.
- If a revision conflict occurs, follow the conflict resolution prompt.

**Save deletion failed**

- Verify that your token has the `save:delete` permission.
